> 둔중한 큰 형태 · 어두운 구조장 · 부분 드러냄 · 3층 색 질서 · 실크스크린 × 파스텔

XXD Panel 005는 Codex와 호환 에이전트를 위한 이미지 생성 Skill입니다. 사진 속 실제 정체성, 동작, 기능과 감정을 보존하고 주제를 한두 개의 둔중하지만 알아볼 수 있는 큰 형태로 압축합니다. 원본의 공간과 의미에서 어두운 구조장을 자라게 하고, 가림·크롭·삼킴·부분 드러냄으로 동화 판화의 서사를 만듭니다.

색은 어두운 구조, 밝은 여백, 아주 작은 고채도 신호의 세 층을 지킵니다. 평면 실크스크린과 가루 같은 파스텔이 드라이 브러시, 입자, 종이결, 분사점, 끊긴 흰색과 미세한 판 어긋남을 남깁니다. 글자는 작은 표지, 사물 패널 또는 가장자리 주석으로만 구조 안에 들어갑니다.

## 왜 005이 필요한가요

일반적인 ‘동화풍’은 어두운 배경에 밝은 색을 고르게 뿌리고 성, 별, 웃는 얼굴을 붙이는 흔한 귀여운 만화로 쉽게 무너집니다.

005은 순서를 뒤집습니다.

```text
원본 사실 고정 → 한두 개의 둔중한 형태로 압축 → 원본에서 어두운 구조장 성장 → 가림과 부분 드러냄으로 서사 구성 → 어두움／밝음／선명색의 세 층 고정 → 실크스크린과 가루 파스텔로 마감
```

무관한 사진으로 바꿔도 큰 형태, 어두운 장의 역할, 가림 논리, 선명색 신호와 문구가 거의 그대로 성립한다면 005가 아닙니다.

## 005의 시각적 원칙

- **한두 개의 둔중한 큰 형태:** 최소 세 가지 원본 고유 단서로 정체성, 동작, 기능과 감정을 보존합니다.
- **원본에서 자라는 어두운 장:** 큰 저명도 구조가 용기, 길, 프레임 또는 밀도 껍질로 분명히 작동합니다.
- **구조적 서사:** 가림, 크롭, 삼킴과 부분 드러냄이 정보의 순서를 만듭니다.
- **평면 그림책 시점:** 압축된 부감, 측면 이동, 정면 프레임, 길 유도, 크기 도약, 가장자리 크롭 중 하나를 선택합니다.
- **3층 색 질서:** 어두운 구조는 무게, 밝은 장은 호흡, 작은 고채도 색은 읽기와 이야기 신호를 맡습니다.
- **성긴 기능선:** 선은 기능, 경로, 경계, 질감과 식별에만 나타납니다.
- **실크스크린 × 파스텔:** 평면 색에 드라이 브러시, 입자, 종이결, 분사점, 끊긴 흰색과 미세한 판 어긋남을 남깁니다.
- **구조 안의 글자:** 둥글고 둔중한 저밀도 작은 표지, 사물 패널 또는 가장자리 주석으로 처리합니다.

## 네 가지 출력, 하나의 판화 논리

네 가지 모드는 하나만 또는 여러 개를 함께 선택할 수 있습니다. `1`, `1+3`, `1、2、4`, `전체`라고 답하면 Skill이 중복을 제거하고 1→4 순서로 실행합니다. 각 모드는 별도 작업 폴더에 독립적으로 출력되며 한 장의 모음 이미지로 합치지 않습니다. `전체`는 원본 한 장당 PNG 7개(일반 모드 각 1개＋배경화면 4개)를 만듭니다. 크기는 모드별로 표시해 같은 답변에서 지정할 수 있고, 지정하지 않은 일반 모드는 원본에 맞춥니다. 문구는 기본적으로 선택한 모드가 공유하며 모드별 지정도 가능합니다.

| 모드 | 크기 규칙 | 결과물 |
| --- | --- | --- |
| `top-bottom` | 원본 적응형 | 위에는 전체 원본, 아래에는 005 동화 판화 구조 서사. 두 패널이 원본 크기를 유지하며 정확히 50/50 |
| `left-right` | 원본 적응형 | 왼쪽에는 전체 원본, 오른쪽에는 005 동화 판화 구조 서사. 두 패널이 원본 크기를 유지하며 정확히 50/50 |
| `design-only` | 원본 적응형 | 원본 사진은 보이지 않고 변환 디자인만 표시. 원본 비율과 크기 유지 |
| `wallpaper-pack` | 기기별 네 가지 크기 | 휴대전화, iPad, 데스크톱, 어린이용 스마트워치 PNG 개별 출력 |

정확한 사용자 픽셀 > 지정 비율 또는 용도 > 일반 모드의 원본 적응형 순서입니다. 원본 `005.md`의 3:4는 초기 창작 캔버스일 뿐 현재 Skill의 숨은 기본값이 아닙니다.

짝을 이루는 모드의 사진은 절제된 색 보정과 필요한 환경 확장만 적용해 사실성을 지킵니다. 디자인 단독과 배경화면은 사진을 근거로 사용하지만 원본을 보여 주지 않습니다.

### 배경화면 세트: 연결형 또는 독립형

배경화면에는 숨은 기본 크기가 없습니다. 일반 프리셋은 휴대전화 `1440×3200`, iPad `2048×2732`, 데스크톱 `3840×2160`, 스마트워치 `1024×1024`이며 기기별 사용자 지정 크기도 가능합니다.

- **연결형 세트(권장):** 먼저 iPad 기준 작품을 생성하고 승인합니다. 나머지 세 기기는 원본 사진＋동일한 기준 작품을 참조해 각 화면에 맞게 새로 구성합니다.
- **독립형 네 작품:** 각 기기는 원본 사진만 참조하며 둔중한 형태, 어두운 장의 역할, 가림 구조, 신호색과 글자 위치를 각각 탐색합니다.

연결형은 크롭이 아닙니다. 네 장 모두 따로 생성하고 구성하며 검수하고, iPad→휴대전화→데스크톱→스마트워치 순으로 참조를 이어 붙이지 않습니다.

## 문구는 판화 구조의 일부여야 합니다

생성 전에 자동 문구, 사용자 지정 문구, 무문자 출력 중 하나를 선택합니다. 문구가 있으면 대상 언어나 지역도 지정합니다.

자동 문구는 주제의 정체성, 보이는 동작, 기능, 관계, 확인된 장소 또는 어두운 장이 맡는 구조적 서사에서 짧은 낱말이나 구절을 추출합니다. 현재 이미지와 긴밀히 묶되 동화를 지어내거나 말장난과 반전을 강요하지 않습니다.

기본은 제목 하나입니다. 실제 정보 가치가 있을 때만 짧은 주석을 0–2개 더하며, 고급스러워 보이기 위해 번호·연도·좌표·아카이브 라벨을 지어내지 않습니다.

사용자가 완성 문구를 주면 그대로 유지합니다. 방향이나 수정 가능한 초안일 때만 대상 독자, 목적, 필수 단어, 어조, 함의를 보존하며 다듬습니다.

언어는 명령문의 언어가 아니라 의도한 독자를 따릅니다.

```text
목표 시장 또는 독자 > 지정한 결과물 언어 > 방향 지시 언어; 모두 불분명하면 생성 전에 질문
```

일본판은 자연스러운 현대 일본어를, 한국 독자용은 자연스러운 현대 한국어와 정확한 띄어쓰기를, 영국판은 영국 영어를 사용합니다. 아랍어판은 기본적으로 자연스러운 현대 표준 아랍어와 올바른 오른쪽에서 왼쪽으로 흐르는 구성을 사용합니다. 외모, 옷, 풍경, 간판으로 국적을 추측하지 않으며 가짜 외국어 문자를 쓰지 않습니다.

## 정확한 기하는 코드가, 작품은 이미지 생성이 맡습니다

이미지 모델이 둔중한 큰 형태, 원본에서 자라는 어두운 구조장, 가림 서사, 3층 색 질서, 실크스크린과 파스텔 재료, 구조 안의 글자를 만듭니다. `scripts/compose_panel.py`는 캔버스 계획, 정확한 50/50 래스터 합성, 최종 크기와 검수만 수행하며 프로그램 그림으로 결과물을 위조하지 않습니다.

```bash
python3 scripts/compose_panel.py --plan --layout top-bottom --source photo.png
python3 scripts/compose_panel.py --plan --layout left-right --size 2560x1440
python3 scripts/compose_panel.py --audit result.png --layout design-only --size 2048x2048
```

정확한 상하 캔버스는 전체 높이, 좌우 캔버스는 전체 너비가 짝수여야 합니다. 요청 픽셀을 몰래 변경하지 않습니다.

## 경계와 신뢰

- 각 사진은 독립된 작업 안에서만 사용하며 다른 입력, 과거 결과, 예시의 피사체, 색, 문구, 구도를 빌리지 않습니다.
- 호출할 때마다 새 작업 폴더를 만들고 원본과 조건이 같아도 새로 생성합니다.
- 결과물은 PNG 비트맵이며 SVG, HTML, Canvas, 프로그램 드로잉 대체물이 아닙니다.
- 설정된 비트맵 브리지는 정제된 상태만 출력하며 공급자, 엔드포인트, 헤더, 인증 정보, 프롬프트, 응답 본문을 노출하지 않습니다.
- 선택한 일반 모드마다 파일 1개를 반환하고, `wallpaper-pack`을 선택하면 독립 배경화면 4개를 추가합니다. `전체`는 원본 한 장당 PNG 7개를 네 개의 동급 모드 폴더에 저장하며 모음 이미지로 합치지 않습니다.

로컬 합성에는 Python 3와 Pillow가 필요합니다. 안전한 비트맵 브리지는 Python 3.11 이상의 `tomllib`을 사용합니다. 이미지 생성에는 내장 래스터 기능이 있는 호스트 에이전트 또는 이미 설정된 호환 경로가 필요합니다.
